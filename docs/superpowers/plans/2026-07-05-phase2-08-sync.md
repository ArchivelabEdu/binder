# Phase 2 — Plan 08: Sync & 이연분 (Omeka S 동기화·생성 UI·saved queries·배포) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 외부 메타데이터 동기화(Omeka S 어댑터 + 필드 소유권/충돌 모델 + 관리·해소 UI), 레코드 생성 UI + 에이전트 CRUD, 리포트 저장(saved_queries), 잔여 백로그 청산, 배포 compose(web/worker 컨테이너)를 구현한다.

**Architecture:** 설계 데이터모델의 sync 3테이블(metadata_sources/node_sources/sync_runs)을 신설하고, 어댑터(packages/integrations, 순수)→동기화 엔진(packages/db, 트랜잭션·소유권·충돌)→워커 큐(sync)→관리 UI(Server Action) 계층을 Plan 06과 동형으로 쌓는다. 충돌 감지는 audit_log origin='user'로, 커서는 소스 high-water mark + 실행별 커서 이원화(설계 원문 그대로). 생성 UI는 편집 폼 인프라를 재사용한다.

**Tech Stack:** 기존 스택 그대로 — 신규 런타임 의존성 0개. Docker 이미지: node:22-slim + pnpm + Next standalone 출력.

## Global Constraints

- import/CSRF/audit/i18n/커밋 규칙: Plan 07과 동일(BINDING) — 상태 변경은 전부 Server Action, 신규 API 라우트 없음(이 계획은 API 라우트 0개 추가), 클라이언트 컴포넌트에서 배럴 금지, 메시지 키에 `.` 금지(중첩 객체 사용 — Plan 07 교훈), ko/en 패리티, conventional commits + `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>`.
- 마이그레이션: 현재 최고 0018. 이 계획은 **0019(Task 1: fixity_recoveries.external_event_ref partial UNIQUE)**, **0020(Task 2: metadata_sources/node_sources/sync_runs/saved_queries 4테이블)** 2개. drizzle-kit generate 후 SQL 검수 필수, 적용 후 `db:generate`가 no-change인지 확인.
- **Omeka S 대상 버전: 4.0+ 추정** (`modified_after` 네이티브 지원 — 4.0 vs 4.1 도입 시점은 출처가 갈림. **Task 3 구현자가 공식 changelog로 최소 버전을 1회 확정하고 README에 그 값을 기록**). 3.x 클라이언트측 컷오프는 명시적 범위 제외.
- Omeka S API 계약(웹 검증 완료, 픽스처 서버의 정본): 인증 = 쿼리 파라미터 `key_identity`+`key_credential`(공개 자료는 익명 가능); 목록 = `GET /api/items?page&per_page&sort_by=modified&sort_order=asc&modified_after=<ISO>` (+`item_set_id` 선택); 총계 헤더 `Omeka-S-Total-Results`, 다음 페이지는 `Link: <...>; rel="next"` 존재 여부; 아이템 = JSON-LD `{ o:id, o:title, o:modified: {@value}, "dcterms:xxx": [{ type: 'literal'|'uri'|'resource:item', property_label, @value?, @language?, @id?, display_title? }] }`.
- **매핑 v1(BINDING, 어댑터→노드)**: `dcterms:title` literal들 → `title` I18nText(`@language`가 'ko'/'en'이면 해당 키, 없으면 첫 literal을 sourceCulture 'ko'에); `dcterms:identifier`(literal `@value` 또는 uri `@id`) → `identifier`; **그 외 모든 프로퍼티의 literal/uri/resource 값** → `sourceAttributes` `[{label: property_label, value: @value ?? o:label ?? display_title ?? @id}]` (프로퍼티 순서 보존); `o:modified` → 커서. `descriptive`는 v1에서 sync가 건드리지 않음(프로파일 crosswalk 인바운드 매핑은 후속 — 주석 명시).
- **원격 소유 필드 v1**: `title`, `identifier`, `sourceAttributes` — 수확 생성 노드의 `field_ownership` = `{ "title": "remote", "identifier": "remote", "sourceAttributes": "remote" }`. 로컬 생성 노드는 node_sources 행 없음(로컬 우선 — 설계 원문).
- 충돌 규칙(설계 원문): 어댑터/엔진은 'remote' 소유 필드만 쓴다; remote 소유 필드가 last_synced_at 이후 audit_log(origin='user', action='update')로 변경된 상태에서 원격도 변경 → `sync_status='conflict'` + `conflicts` JSONB `[{field, local, remote}]` → UI 수동 해소.
- 시크릿: DB에 자격증명 저장 금지 — `metadata_sources.auth_config_ref`는 **env 접두어 문자열**; 어댑터는 `process.env[`${ref}_KEY_IDENTITY`]`/`..._KEY_CREDENTIAL`을 읽는다(비어 있으면 익명). `.env.example`에 `OMEKA_DEMO_KEY_IDENTITY=`/`OMEKA_DEMO_KEY_CREDENTIAL=` 예시.
- 큐 계약 확장: `QUEUES.sync = 'sync'`, 페이로드 `type SyncJobPayload = { syncRunId: number }`. 크론 없음 — v1은 관리 UI 수동 트리거만(SYNC_CRON은 백로그).
- 게이트(전 태스크): `pnpm test` + `pnpm typecheck` + `pnpm --filter web build` 그린. e2e는 Task 9(총 12본 목표: 기존 9 + 생성/소스/saved-report 3).
- 배포(Task 9): `next.config.ts`에 `output: 'standalone'` 추가(dev/e2e 무영향 확인 필수); compose에 `profiles: ["app"]`로 web/worker 서비스 추가 — **기본 `pnpm db:up` 동작 불변**(profile 미지정 시 pg+redis만).

export const nodeSources = pgTable('node_sources', {
  id: serial('id').primaryKey(),
  nodeId: integer('node_id').notNull().references(() => nodes.id, { onDelete: 'cascade' }),
  sourceId: integer('source_id').notNull().references(() => metadataSources.id, { onDelete: 'restrict' }),
  sourceRecordId: text('source_record_id').notNull(),
  sourceRecordUrl: text('source_record_url'),
  remotePayloadHash: text('remote_payload_hash'),
  rawPayload: jsonb('raw_payload').$type<Record<string, unknown>>(),

  uniqueIndex('node_sources_source_record_uq').on(t.sourceId, t.sourceRecordId),
  uniqueIndex('node_sources_node_source_uq').on(t.nodeId, t.sourceId),
]);

export const syncRuns = pgTable('sync_runs', {
  id: serial('id').primaryKey(),
  sourceId: integer('source_id').notNull().references(() => metadataSources.id, { onDelete: 'restrict' }),
  kind: syncRunKindEnum('kind').notNull(),
  cursor: text('cursor'),
  stats: jsonb('stats').$type<{ fetched: number; created: number; updated: number; conflicted: number; skipped: number }>(),

});
